# GitHub 전용 릴리즈 절차

[English](releasing.md)

웹스토어 등록은 보류 상태이며 자동 게시 작업은 없습니다. 아래는 게시자가 승인한 뒤 사용할 절차입니다.

1. 매니페스트·패키지·잠금파일의 버전, 변경 기록, 개인정보 설명을 함께 갱신합니다.
2. 타입·포맷·빌드, 정보 정제·취소 회귀 검사, 가상 문서 내보내기, 영어·한국어 오프라인 뷰어, 이미지 검사를 수행합니다.
3. `npm run audit:source`, 정확한 스테이징 파일과 릴리즈 ZIP의 독립 비밀정보 검사, 텍스트·이미지 수동 검수를 수행합니다. 실제 논문·식별자·계정·프로필·PC 경로·IP 주소·비공개 검수 로그는 공개하지 않습니다. 승인된 공개 게시자·문의 정보와 글꼴 고지는 예외입니다.
4. `npm run release:prepare`로 `dist/release/` 아래 버전 ZIP과 `SHA256SUMS.txt`를 만듭니다. 로컬 생성만 하며 커밋·태그·푸시·외부 게시를 하지 않습니다.
5. `git diff --cached`, `git diff`, 이미지와 문서 링크를 확인하고 공개할 최종 내용을 승인합니다.
6. 승인 후 검수한 소스를 커밋·푸시합니다. GitHub **Releases → Draft a new release**에서 검수한 커밋에 `v1.0.2` 같은 버전 태그를 지정하고 변경 기록을 설명으로 작성합니다.
7. 해당 버전 ZIP과 체크섬만 첨부하고 초안의 버전·파일을 재확인한 뒤 게시합니다. 초안·태그·업로드도 외부 작업이므로 게시자 승인 후 수행합니다.
8. 게시 파일을 다시 받아 해시와 새 Chrome 프로필 설치를 확인하고, GitHub README 이미지·링크도 확인해야 게시 완료로 판단합니다.

개발자 모드 설치는 GitHub 자동 업데이트가 되지 않습니다. 새 릴리즈를 받아 설치 폴더를 교체하고 확장 및 원본 리뷰 탭을 새로고침합니다. [설치 안내](chrome-extension-install.md).
